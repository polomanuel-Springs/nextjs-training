# What I understood

- I learned that a Server Action lets a form trigger server-side work.
- The use server directive marks server functions, and FormData carries fields identified by name.
- I validate input and verify the user inside the action itself.
- A successful mutation can be followed by revalidatePath and redirect.
- Credentials for a backend service stay in server-only environment variables.
- Persistence belongs to the configured service or database, not an unverified success message.
